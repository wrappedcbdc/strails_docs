Before you write your first integration, read through these concepts. They explain the patterns that appear in every Strails endpoint and will save you debugging time later.

## Asynchronous Processing

Every blockchain operation in Strails — wallet creation, token minting, swaps, transfers — returns a response in approximately **200ms** without waiting for on-chain confirmation. Instead of blocking, the API issues a `requestId` immediately and processes the operation in the background:

```json
{
  "status": "success",
  "response_code": "00",
  "data": {
    "requestId": "req_abc123",
    "status": "requested"
  }
}
```

Track the final outcome in one of two ways:

- **Webhooks (recommended):** Strails posts the result to your configured endpoint as soon as the operation completes. This is the most reliable approach and avoids unnecessary polling.
- **Status polling:** Call the corresponding status endpoint (for example, `/cngnonrampstatus`) with the `requestId` until the status transitions from `requested` or `pending` to `completed` or `failed`.

Store every `requestId` you receive. It is the only way to recover or query the status of an operation later.

## Virtual Accounts

Virtual accounts are Nigerian bank accounts generated by Strails on behalf of your fintech or your users. Any NGN deposited to a virtual account is automatically converted to cNGN and credited to the associated wallet.

| Type | Assigned To | Lifetime |
|---|---|---|
| Fintech Permanent | Your fintech entity | Permanent — reusable across multiple deposits |
| User Permanent | A specific end user | Permanent — tied to the user's wallet for life |
| Transaction Temporary | A single funding request | 30 minutes — expires after the transaction window |

Transaction-scoped accounts are created by the `/cngnonramp` endpoint. Display the account details to your user and make clear they must complete payment within 30 minutes. After expiry, the account can no longer receive deposits.

## Wallet System

Your fintech operates with three distinct wallet types. Each serves a different purpose and has a different control model:

| Wallet | Holds | Control |
|---|---|---|
| Multi-Chain Wallet | cNGN, USDC, USDT | Strails-controlled HSM-managed wallet |
| Smart Wallet | cNGN, USDC, USDT | Fintech- or Strails-controlled smart contract wallet |
| MPC Wallet | USDC, USDT | Fintech-controlled with MPC co-signing |

Token balances for day-to-day operations live in the **Smart Wallet** and **Multi-Chain (Managed) Wallet**. The **MPC Wallet** (also called the MPC Vault) is used for higher-value custody and FX trading, where your fintech co-signs transactions for maximum security.

Retrieve your wallet addresses at any time with `GET /getfintechwallet`.

## FX Orderbook

Strails runs a peer-to-peer orderbook where fintechs trade cNGN against USDC and USDT. Key mechanics:

- **Limit orders:** Post a price and an amount range. Your order stays active until a counterparty matches it or you cancel it.
- **Market orders:** Execute immediately at the best available price on the book.
- **Escrow settlement:** When a trade is matched, both sides' tokens are held in escrow. Settlement releases automatically once both sides confirm or the 5-minute price lock expires.
- **Price lock:** A matched quote is guaranteed for 5 minutes. If the trade is not executed within that window, the quote expires and must be refreshed.
- **Self-trading prevention:** The engine automatically blocks orders where buyer and seller are the same fintech.
- **Auto-approval:** Trades that fall within your configured approval threshold are automatically executed by a dedicated virtual machine without manual intervention.

## Webhooks

Strails sends a real-time POST notification to your configured webhook URL whenever a critical operation completes or changes state. Events cover:

- Wallet creation and balance changes
- Deposit confirmations and onramp completions
- Offramp initiation, processing, and settlement
- FX order matching, trade execution, and settlement
- User onboarding status changes

There are **22 event types** in total. See [Webhook Events](/api-reference/webhook-events) for the full list and payload schemas.

### Security

Every webhook request includes two headers:

- `X-Strails-Signature` — an HMAC-SHA256 signature computed over the timestamp and request body using your webhook secret.
- `X-Strails-Timestamp` — a Unix timestamp you can use to reject replayed requests.

Verify the signature on every incoming request:

```javascript
const crypto = require('crypto');

function verifyWebhookSignature(req, secret) {
  const signature = req.headers['x-strails-signature'];
  const timestamp  = req.headers['x-strails-timestamp'];
  const payload    = JSON.stringify(req.body);

  const expected = crypto
    .createHmac('sha256', secret)
    .update(`${timestamp}.${payload}`)
    .digest('hex');

  return signature === expected;
}
```

Strails retries failed deliveries with exponential backoff. Your endpoint must return `200 OK` immediately and process the event asynchronously to avoid unnecessary retries.

## Amount Formats

The API uses **two different amount conventions** depending on whether the operation involves fiat or tokens. Mixing them up is the most common source of integration bugs.

### Fiat Operations (Onramp / Offramp / Virtual Accounts)

Pass amounts in **whole Naira**. Do not use kobo:

```json
{
  "amount": 5000
}
```

This means ₦5,000 — not 5,000 kobo (₦50). Examples:

- Create virtual account: `"amount": 5000` → user pays ₦5,000
- Initiate onramp: `"amount": 200` → costs ₦203 including fees
- Initiate offramp: `"amount": 3000` → user receives ₦3,000 in their bank account

### Token Operations (Blockchain Transfers / Balances)

Pass amounts in the **smallest unit** for the token (wei-style), based on the token's decimal precision:

| Token | Decimals | Example |
|---|---|---|
| cNGN | 6 | `500000000` = 500 cNGN |
| USDC | 6 | `1000000` = 1 USDC |
| USDT | 6 | `1000000` = 1 USDT |
| DAI | 18 | `1000000000000000000` = 1 DAI |

Convert between display values and raw amounts in JavaScript:

```javascript
// Blockchain response → human-readable display
const displayAmount = Number("500000000") / 1e6; // = 500 cNGN

// User input → raw amount for the request body
const rawAmount = String(Math.floor(123.45 * 1e6)); // = "123450000"
```

<Warning>
  **Remember:** Fiat endpoints (onramp, offramp, virtual accounts) use whole Naira. Only blockchain and token endpoints use the smallest-unit (wei) format. Check the endpoint's documentation if you are unsure which convention applies.
</Warning>

## Response Format

Every API response uses the same JSON envelope regardless of success or failure.

**Success (HTTP 200):**

```json
{
  "status": "success",
  "response_code": "00",
  "message": "Operation completed successfully",
  "data": {
    "requestId": "req_abc123"
  }
}
```

**Error (HTTP 4xx / 5xx):**

```json
{
  "status": "error",
  "response_code": "01",
  "message": "Validation error: Invalid amount",
  "error": {
    "field": "amount",
    "reason": "Must be greater than 0"
  }
}
```

### Response Codes

The `response_code` field gives you a machine-readable status you can switch on in your code, independently of the HTTP status code:

| Code | Meaning |
|---|---|
| `00` | Success |
| `01` | Validation Error — check the `error` field for the offending field and reason |
| `02` | Not Found — the requested resource does not exist |
| `03` | Unauthorized — invalid or missing API key, or IP not in allowlist |
| `04` | Rate Limited — slow down and implement exponential backoff |
| `05` | Internal Error — a Strails-side error; contact support if it persists |

For detailed request and response payloads per endpoint, see [API Reference](/api-reference/index).
