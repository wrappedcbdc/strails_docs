Execute trades against the Strails FX orderbook using one of three execution modes: quote-based (recommended for price certainty), direct market (best available price), or targeted (against a specific liquidity provider's order). All trades settle through an on-chain escrow: your cNGN is locked at the time of matching and released to the counterparty only after the blockchain transaction confirms. Use the status endpoints to track each trade through its full lifecycle.

## Get Quote

Generate a price quote by matching your requested cNGN amount against live orderbook liquidity. The response includes the matched order(s), the resulting stablecoin amount you will receive, and a `quoteId` you can pass directly to `POST /fx/trade`. The quote is valid for 15 minutes.

<Note>
  Quotes expire exactly 15 minutes after generation, and each `quoteId` can be executed only once. If you pass an expired or already-used `quoteId` to `POST /fx/trade`, the request is rejected with `INVALID_QUOTE`. Generate a fresh quote and retry.
</Note>

If no single order can fill your amount, the quote combines several orders. See [How orders are matched](#how-orders-are-matched).

<Tabs>
  <Tab title="Request">
    ```bash
    curl --request POST \
      --url https://api.strails.io/v1/fx/quote \
      --header "x-api-key: <API_KEY>" \
      --header "Content-Type: application/json" \
      --data '{
        "pair": "CNGN-USDC",
        "side": "sell",
        "cngnAmount": "50000"
      }'
    ```

    <ParamField body="pair" type="string" required>
      Trading pair in the format `CNGN-TOKEN`. Accepted values: `"CNGN-USDC"` or `"CNGN-USDT"`.
    </ParamField>

    <ParamField body="side" type="string" required>
      Trade direction. Use `"sell"` to exchange cNGN for the quote currency, or `"buy"` to acquire cNGN by spending the quote currency.
    </ParamField>

    <ParamField body="cngnAmount" type="string">
      The cNGN amount to trade, expressed as a human-readable decimal (e.g., `"50000"` means 50,000 cNGN). Provide this **or** `tokenAmount`, not both. Minimum is 1,000 cNGN.
    </ParamField>

    <ParamField body="tokenAmount" type="string">
      The pair-currency amount to trade, expressed as a human-readable decimal (e.g., `"37.04"` for USDC or `"37.04"` for USDT). Use this when you want the quote denominated in the pair token instead of cNGN. Provide this **or** `cngnAmount`, not both.
    </ParamField>
  </Tab>

  <Tab title="Response">
    ```json
    {
      "status": "Success",
      "response_code": "00",
      "message": "Quote generated successfully",
      "data": {
        "quote": {
          "quoteId": "quote_7f3a9d2c-8e41-4b29-9a1c-5d8e7f2b3a9c",
          "pair": "CNGN-USDC",
          "side": "sell",
          "cngnAmount": "50000",
          "usdcAmount": "37.04",
          "price": "1350.00",
          "matchedOrders": [
            {
              "orderId": "order_abc123",
              "price": "1350.00",
              "cngnAmount": "50000",
              "usdcAmount": "37.04"
            }
          ],
          "expiresAt": "2026-05-01T10:35:00.000Z"
        },
        "version": "1.0.0"
      }
    }
    ```

    <ResponseField name="data.quote.quoteId" type="string">
      Unique quote identifier. Pass this to `POST /fx/trade` to execute at the quoted price.
    </ResponseField>

    <ResponseField name="data.quote.cngnAmount" type="string">
      The cNGN amount this quote is priced for.
    </ResponseField>

    <ResponseField name="data.quote.usdcAmount" type="string">
      The stablecoin amount you will receive (or spend) if you execute this quote. Field name is dynamic based on the pair: `usdcAmount` or `usdtAmount`.
    </ResponseField>

    <ResponseField name="data.quote.price" type="string">
      The effective exchange rate used for this quote (cNGN per stablecoin unit, human-readable).
    </ResponseField>

    <ResponseField name="data.quote.matchedOrders" type="array">
      The orderbook orders matched to fill this quote. Each entry shows the contributing order's price and amounts.
    </ResponseField>

    <ResponseField name="data.quote.expiresAt" type="string">
      ISO 8601 UTC timestamp after which this quote can no longer be executed.
    </ResponseField>
  </Tab>
</Tabs>

## Execute Trade

Execute an FX trade. Choose from three execution modes depending on how much price certainty and targeting you need.

<Note>
  Before calling this endpoint, ensure the cNGN you intend to trade is held in your Fintech Smart Wallet. You can retrieve your smart wallet address from `GET /getfintechwallet`.
</Note>

<Tabs>
  <Tab title="Mode 1 - Quote (Recommended)">
    Execute against a quote you obtained from `POST /fx/quote`. This mode locks in the price shown in the quote and is the safest choice to avoid slippage.

    ```bash
    curl --request POST \
      --url https://api.strails.io/v1/fx/trade \
      --header "x-api-key: <API_KEY>" \
      --header "Content-Type: application/json" \
      --data '{
        "quoteId": "quote_7f3a9d2c-8e41-4b29-9a1c-5d8e7f2b3a9c",
        "idempotencyKey": "trade_20260501_001"
      }'
    ```

    <ParamField body="quoteId" type="string" required>
      The `quoteId` returned by `POST /fx/quote`. The quote must not be expired (valid for 15 minutes) or already used.
    </ParamField>

    <ParamField body="idempotencyKey" type="string">
      An optional client-generated key to prevent duplicate trade submissions. If you retry a request with the same key and the original trade was accepted, the original trade is returned instead of creating a new one.
    </ParamField>
  </Tab>

## Create Market Order

Submit an immediate market order that executes at the current best available price from the orderbook. Market orders skip the quote step and settle based on your auto-signing configuration.

<Note>
  Market orders execute against the best available limit orders at the time of submission, combining several orders if needed (see [How orders are matched](#how-orders-are-matched)). If orderbook liquidity changes between your request and matching, the final fill price may differ slightly from what you observed in the orderbook stats. Use `POST /fx/quote` followed by `POST /fx/trade` (Mode 1) if exact price certainty is required.
</Note>

## How orders are matched

Quote-based (Mode 1), direct (Mode 2), and market-order trades are matched against the orderbook in the same way:

- Strails considers the 10 best-priced active orders on the opposite side of your trade: the lowest-priced `sell` orders when you buy, and the highest-priced `buy` orders when you sell.
- Your amount fills those orders in price order. If the best order cannot cover the full amount, the remainder spills into the next order, so one trade can fill across several liquidity providers. Each contributing order appears in the quote's `matchedOrders` array, and `price` is the volume-weighted average.
- An order is skipped if the amount still to fill is below its `minAmount`, if it has no remaining capacity, or if the liquidity provider's wallet does not currently hold enough funds to honour it.
- Quotes never include your own orders.

Targeted trades (Mode 3) always execute against exactly one order.

### Insufficient liquidity

A trade fills completely or not at all. If the matched orders cannot cover your full amount, the request is rejected with `NO_LIQUIDITY` and no trade is created. The `message` explains why, for example that your amount is below the smallest available `minAmount`, that the matching liquidity providers' wallets are underfunded, or that only part of the amount could be matched. Reduce your amount, split it into smaller trades, or retry when more liquidity is available.

### Multi-order settlement

When a trade fills across more than one order, each order is settled as its own slice:

- **Buy trades** need no MPC signature, so they move straight from `locked` to `settling`.
- **Sell trades** need each liquidity provider to sign the stablecoin transfer for their own slice, within the 15-minute price lock.

If every slice settles, the trade is `completed`. If some slices of a sell trade settle and others fail or expire (for example, because one liquidity provider did not sign in time), the trade ends as `partial`: the settled slices are final, the cNGN for the unsettled slices is refunded from escrow, and the trade is flagged for review by Strails. If no slice settles, the trade is `failed`.

## Trade Status Lifecycle

Every trade passes through the following statuses as it progresses from submission to final settlement:

| Status                 | Description                                                                     |
| ---------------------- | ------------------------------------------------------------------------------- |
| `pending`              | Trade submitted and parameters are being validated.                             |
| `locked`               | cNGN locked in escrow. The 15-minute price lock is running.                     |
| `signing`              | Awaiting MPC Vault signature to authorise the blockchain transaction.           |
| `settling`             | Signed transaction ready for settlement on the blockchain.                      |
| `settling_in_progress` | Settlement is actively executing on-chain. If settlement stops before reaching a final status, the trade returns to `settling`. |
| `completed`            | Settlement confirmed. Tokens transferred to all parties.                        |
| `partial`              | Multi-order trades only. Some slices settled; the others failed or expired and their cNGN was refunded. |
| `failed`               | Trade failed at the `signing` or `settling` stage. Check `errorMessage`.        |
| `expired`              | The 15-minute price lock elapsed before the trade reached `settling`.           |

### Status Flow

```text
pending --> locked --> signing --> settling --> settling_in_progress --> completed
                          |                              |
                          +--> failed                    +--> partial  (multi-order trades only)
                          |                              |
                          +--> expired                   +--> failed

locked --> expired  (if the 15-minute price lock elapses)
```

`completed`, `partial`, `failed`, and `expired` are final. When a trade expires or fails, the escrowed cNGN is automatically released back to your wallet.

### FX error codes

When a quote or trade is rejected by the trading engine, the specific reason is returned in `data.details.errorCode`. Requests that fail schema validation return `response_code` `01` with the field errors in `data.details.details` and no `errorCode`.

```json
{
  "status": "Failed",
  "response_code": "02",
  "message": "No liquidity available for CNGN-USDC sell orders. No liquidity providers have placed matching orders for this trading pair.",
  "data": {
    "details": {
      "errorCode": "NO_LIQUIDITY",
      "version": "1.0.0"
    }
  }
}
```

| `errorCode`                | `response_code` (HTTP) | Endpoints                       | Description                                                            |
| -------------------------- | ---------------------- | ------------------------------- | ---------------------------------------------------------------------- |
| `INVALID_QUOTE`            | `01` (400)             | Trade                           | The `quoteId` does not exist, belongs to another fintech, has expired, or has already been used. |
| `NO_LIQUIDITY`             | `02` (404)             | Quote, trade, market order      | The orderbook cannot fill the full amount. See [Insufficient liquidity](#insufficient-liquidity). |
| `FINTECH_NOT_FOUND`        | `02` (404)             | Quote, trade, market order      | No fintech wallet is configured for your account.                      |
| `TRADING_SUSPENDED`        | `05` (500)             | Trade, market order             | Your fintech is suspended from FX trading after repeated manual signing failures. The `message` gives the reason. |
| `ORDER_UNAVAILABLE`        | `05` (500)             | Trade, market order             | The matched order no longer exists. Request a fresh quote.             |
| `ORDER_NOT_ACTIVE`         | `05` (500)             | Trade, market order             | The matched or targeted order is no longer active. Request a fresh quote or choose another order. |
| `INVALID_ORDER_DATA`       | `05` (500)             | Trade, market order             | The matched order data is invalid. Request a fresh quote.              |
| `INVALID_LP_DATA`          | `05` (500)             | Trade, market order             | The matched order has no liquidity provider attached. Request a fresh quote. |
| `ORDER_NOT_FOUND`          | `05` (500)             | Trade (Mode 3)                  | The targeted `orderId` does not exist.                                 |
| `SELF_TRADING_NOT_ALLOWED` | `05` (500)             | Trade (Mode 3)                  | The targeted order belongs to your own fintech.                        |
| `AMOUNT_BELOW_MINIMUM`     | `05` (500)             | Trade (Mode 3)                  | `cngnAmount` is below the targeted order's `minAmount`.                |
| `AMOUNT_EXCEEDS_MAXIMUM`   | `05` (500)             | Trade (Mode 3)                  | `cngnAmount` is above the targeted order's `maxAmount`.                |
| `INSUFFICIENT_LIQUIDITY`   | `05` (500)             | Trade (Mode 3)                  | The liquidity provider's wallet does not hold enough funds to fill the targeted order. |
| `QUOTE_GENERATION_FAILED`  | `05` (500)             | Quote                           | Unexpected error while generating the quote. Retry.                    |
| `TRADE_EXECUTION_FAILED`   | `05` (500)             | Trade, market order             | Unexpected error while creating the trade. Retry.                      |
| `ORDER_EXECUTION_FAILED`   | `05` (500)             | Trade (Mode 3)                  | Unexpected error while creating the targeted trade. Retry.             |

<Warning>
  Several client-side rejections (for example `SELF_TRADING_NOT_ALLOWED` and `AMOUNT_BELOW_MINIMUM`) are returned with `response_code` `05` and HTTP 500. Branch on `data.details.errorCode`, not on the HTTP status, and do not retry these blindly.
</Warning>

## Additional Notes

<Note>
  All cNGN and stablecoin amounts in request bodies use human-readable decimal notation (e.g., `"50000"` = 50,000 cNGN). All amounts in orderbook fields (`price`, `minAmount`, `maxAmount`, `availableLiquidity`) use the smallest unit with 6 decimal places. Divide those values by 1,000,000 to convert to human-readable form.
</Note>

<Note>
  Quotes and trade price locks both expire after exactly 15 minutes. Structure your integration to execute the trade immediately after generating a quote, and to poll `GET /fx/trade/status` for settlement confirmation rather than relying on synchronous responses.
</Note>
