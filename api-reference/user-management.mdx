The User Management API lets you register end-users on Strails using their Bank Verification Number (BVN), track the async KYC process through to completion, fetch full user profiles including wallet addresses and virtual accounts, control user account status, and route a user's cNGN deliveries to an external default wallet. Because BVN verification is handled by an external identity provider, all onboarding requests are processed asynchronously - you receive a `requestId` immediately and poll or listen for the result.

## Endpoints Overview

| Section | Endpoint | Method | Description |
|---|---|---|---|
| [Onboard User](#post-onboarduser) | `/onboarduser` | POST | Initiate BVN-based KYC and create a new user account. |
| [Onboard Status](#post-onboardstatus) | `/onboardstatus` | POST | Check the current status of a pending onboarding request. |
| [Get User Details](#post-getuserdetails) | `/getuserdetails` | POST | Retrieve a user's full profile, wallets, and virtual accounts. |
| [Manage User Status](#post-manageuserstatus) | `/manageuserstatus` | POST | Activate or deactivate a user account with an audit reason. |
| [List Fintech Users](#post-listfintechusers) | `/listfintechusers` | POST | Retrieve a paginated list of all users belonging to your fintech. |
| [Set User Default Wallet](#post-setuserdefaultwallet) | `/setuserdefaultwallet` | POST | Route a user's cNGN deliveries to an external wallet address. |
| [Get User Default Wallet](#post-getuserdefaultwallet) | `/getuserdefaultwallet` | POST | Retrieve the external default wallet currently set for a user. |

### POST /onboarduser {#post-onboarduser}

Initiates onboarding for a new user by submitting their 11-digit BVN for identity verification. The request is processed asynchronously - use the returned `requestId` to poll `/onboardstatus`, or wait for the [`user.onboarded`](/api-reference/webhook-events) webhook event.

```bash
curl -X POST https://api.strails.io/v1/onboarduser \
  -H "Content-Type: application/json" \
  -H "x-api-key: YOUR_SECRET_API_KEY" \
  -d '{
    "bvn": "12345678901"
  }'
```

#### Request Parameters

<ParamField body="bvn" type="string" required>
  The user's 11-digit Bank Verification Number. Must be exactly 11 numeric digits and must not belong to an existing Strails user.
</ParamField>

<Note>
  `bvn` is the **only** field this endpoint accepts. Identity details (names, phone, date of birth) are resolved from the BVN record, and the user's identifier is issued by Strails and returned as `userHash` - do not supply your own `userId`.
</Note>

#### Response

```json
{
  "status": "Success",
  "response_code": "00",
  "message": "User registration initiated",
  "data": {
    "requestId": "7898f29e-10a6-4b2b-9496-f4ee50549fd4",
    "status": "processing",
    "userHash": "user_uniqueID",
    "message": "User registration request has been submitted for processing",
    "estimatedCompletionTime": "2-5 minutes"
  }
}
```

<Info>
  Store the `requestId` returned here - you will need it to check onboarding status via `/onboardstatus`.
</Info>

#### Error Responses

```json
{
  "status": "Error",
  "response_code": "01",
  "message": "Validation error",
  "error": "Invalid BVN format. BVN must be 11 digits"
}
```

```json
{
  "status": "Error",
  "response_code": "01",
  "message": "User already exists",
  "error": "A user with this BVN is already registered"
}
```

```json
{
  "status": "Error",
  "response_code": "05",
  "message": "BVN verification failed",
  "error": "Unable to verify BVN with identity provider"
}
```

### POST /onboardstatus {#post-onboardstatus}

Checks the current status of a pending user onboarding request using the `requestId` returned by `/onboarduser`. Poll this endpoint until `status` is `"completed"` or `"failed"`, or handle the [`user.onboarded`](/api-reference/webhook-events) webhook event instead.

```bash
curl -X POST https://api.strails.io/v1/onboardstatus \
  -H "Content-Type: application/json" \
  -H "x-api-key: YOUR_SECRET_API_KEY" \
  -d '{
    "requestId": "7898f29e-10a6-4b2b-9496-f4ee50549fd4"
  }'
```

#### Request Parameters

<ParamField body="requestId" type="string" required>
  The unique identifier returned by `/onboarduser` when the registration was initiated.
</ParamField>

#### Response

```json
{
  "status": "Success",
  "response_code": "00",
  "message": "User registration completed successfully",
  "data": {
    "type": "user_registration",
    "userId": "user_uniqueID",
    "status": "completed",
    "createdAt": "2026-01-18T19:33:39.945Z",
    "message": "User registration completed successfully"
  }
}
```

Once `status` is `"completed"`, use the `userId` from the response to call `/getuserdetails` and retrieve the user's full profile.

#### Error Responses

```json
{
  "status": "Error",
  "response_code": "02",
  "message": "Request not found",
  "error": "No onboarding request found with the provided requestId"
}
```

### POST /manageuserstatus {#post-manageuserstatus}

Activates or deactivates a user account. When deactivating, you must supply a `reason` - this is recorded in the audit trail. Deactivated users cannot initiate transactions or receive deposits until reactivated.

```bash
curl -X POST https://api.strails.io/v1/manageuserstatus \
  -H "Content-Type: application/json" \
  -H "x-api-key: YOUR_SECRET_API_KEY" \
  -d '{
    "userId": "user_uniqueID",
    "active": false,
    "reason": "Account suspended by customer request"
  }'
```

#### Request Parameters

<ParamField body="userId" type="string" required>
  The unique identifier of the user whose status you want to change.
</ParamField>

<ParamField body="active" type="boolean" required>
  Set to `true` to activate the account or `false` to deactivate it.
</ParamField>

<ParamField body="reason" type="string">
  A human-readable explanation for the status change. **Required when `active` is `false`.** Recorded in the audit log for compliance purposes.
</ParamField>

#### Response

```json
{
  "status": "Success",
  "response_code": "00",
  "message": "User deactivated successfully",
  "data": {
    "userId": "user_uniqueID",
    "active": false,
    "changedAt": "2025-12-16T09:17:33.658Z"
  }
}
```

#### Error Responses

```json

  "status": "Error",

}
```


## User Default Wallet

By default, cNGN disbursed for a user is delivered to the Strails-managed smart wallet provisioned during onboarding. Setting an **external default wallet** redirects those deliveries to an address you control on behalf of the user - useful when the user self-custodies or when your fintech settles into its own treasury addresses.

The external default wallet applies to three delivery paths only:

- cNGN disbursed from a deposit into the user's permanent virtual account
- cNGN disbursed through `/cngnonramp`
- Tokens swept when `sweepToOfframp` is enabled

Deposit and funding webhooks fire as normal; the destination address in the payload reflects the external wallet.

<Warning>
  An external default wallet is a **delivery destination only**. Strails holds no keys for it, so swaps, offramp, and escrow continue to operate against the user's Strails-managed wallet and never against this address. Funds delivered here must be moved by whoever holds the keys.
</Warning>

### POST /setuserdefaultwallet {#post-setuserdefaultwallet}

Sets or replaces the external default wallet for a user. Calling this endpoint again with a different address overwrites the existing configuration. The address must be valid for the specified blockchain.

```bash
curl -X POST https://api.strails.io/v1/setuserdefaultwallet \
  -H "Content-Type: application/json" \
  -H "x-api-key: YOUR_SECRET_API_KEY" \
  -d '{
    "userId": "user_uniqueID",
    "address": "0xc5422E03B8250917023501E4697c738E7427b540",
    "blockchain": "base",
    "label": "User payout wallet"
  }'
```

#### Request Parameters

<ParamField body="userId" type="string" required>
  The unique identifier of the user the wallet belongs to.
</ParamField>

<ParamField body="address" type="string" required>
  The external EVM wallet address (`0x...`) that should receive the user's cNGN deliveries.
</ParamField>

<ParamField body="blockchain" type="string">
  The EVM network the address belongs to (e.g. `base`, `eth`, `bsc`). Defaults to `base`. A network other than Base is accepted only when bridged settlement is available - see [Settlement Network](#settlement-network).
</ParamField>

<ParamField body="label" type="string">
  A human-readable name for the wallet (e.g. `User payout wallet`).
</ParamField>

#### Response

```json

  "status": "Success",
  "response_code": "00",
  "message": "Default wallet set successfully",
```

<ResponseField name="data.defaultWallet.status" type="string">
  Whether the wallet is currently receiving deliveries. `active` once set.

<ResponseField name="data.note" type="string">
  Plain-language reminder of the delivery-only behaviour of external default wallets.
</ResponseField>

#### Error Responses

```json
{
  "status": "Error",
  "response_code": "02",
  "message": "User not found",
  "error": "No verified user found with the provided userId"
}
```

```bash
  }'
```

#### Request Parameters

<ParamField body="userId" type="string" required>
  The unique identifier of the user whose default wallet you want to clear.
</ParamField>

#### Response

```json
{
  "status": "Success",
  "response_code": "00",
  "message": "Default wallet removed successfully",
  "data": {
    "userId": "user_uniqueID",
```

## Settlement Network

The **settlement network** is the chain a user's onramp cNGN is delivered on. Unless you set one, every onramp settles on Base. You can set a network per user, set a default for all of your users, or name one on a single [`/cngnonramp`](/api-reference/transactions#user-onramp) request.

It applies to cNGN disbursed from a deposit into the user's permanent virtual account and to cNGN disbursed through `/cngnonramp`.

### How the network is chosen

Strails uses the first of these that is set:

1. `settlementNetwork` on the `/cngnonramp` request (that request only, optionally with a `settlementAddress`)
2. The user's settlement network, set with [`/setusersettlementnetwork`](#post-setusersettlementnetwork)
3. The network the user's [external default wallet](#user-default-wallet) is registered for
4. Your fintech's default, set with [`/setfintechsettlementnetwork`](#post-setfintechsettlementnetwork)
5. Base

Because steps 2 and 3 outrank step 4, a fintech default never overrides a user who has their own setting or an external default wallet.

### Where the cNGN lands

A `/cngnonramp` request that sends `settlementAddress` is delivered to that address, whatever the user has registered. Otherwise:

Off Base, cNGN is delivered **only to an external default wallet registered for that network**. The user's Strails-managed smart wallet exists only on Base, so it is never a destination on another chain. On Base, cNGN goes to the user's external default wallet if it is registered for Base, otherwise to their smart wallet.

| Network | Destination |
|---|---|
| Base | External default wallet registered for Base, otherwise the user's smart wallet |
| Other EVM networks (`bsc`, `eth`, `pol`, `atc`, `lisk`, `monad`, `arc`, `celo`) | External default wallet registered for that network |
| Tron, Solana, Bantu (`trx`, `sol`, `xbn`) | None today - external default wallets must be EVM addresses |

Use [`/listusersettlementdestinations`](#post-listusersettlementdestinations) to check where a user can be paid before you pick a network.

<Info>
  Strails bridges the cNGN from Base to the settlement network and **absorbs the bridge fee**, so the user receives the same amount they would have received on Base. A bridged deposit is reported complete only after the bridge releases the cNGN on the destination network. If a bridge transfer can't be started (for example, the amount is above the bridged-settlement limit), the cNGN is delivered on Base instead.
</Info>

<Warning>
  Permanent virtual account deposits always settle to a registered wallet, so a user's settlement network other than Base needs an external default wallet on that network - `/setusersettlementnetwork` refuses it otherwise. If a user has no address on the resolved network, a permanent virtual account deposit is **held** rather than paid on another network, and Strails is alerted.

  A `/cngnonramp` request that names such a network in `settlementNetwork` without a `settlementAddress` is refused when you make it. For a `/cngnonramp` payment where the network comes from a stored setting instead, the cNGN is delivered on Base.
</Warning>

#### Network values

`base`, `bsc`, `eth`, `pol`, `trx`, `sol`, `xbn`, `atc`, `lisk`, `monad`, `arc`, `celo`. Common names such as `ethereum`, `polygon`, `bnb`, and `celo chain` are also accepted and normalised to these codes.

A network other than Base can be stored only while bridged settlement is available on Strails. Otherwise the set endpoints, and `/cngnonramp`, return:

```json
{
  "status": "Failed",
  "response_code": "01",
  "message": "Settlement on BNB Smart Chain is not available yet; only Base is supported"
}
```

### POST /setusersettlementnetwork {#post-setusersettlementnetwork}

Sets the network a user's onramps settle on. Strails stores the network only if the user already has an address that can receive on it, so a stored setting is always one the onramp can honour.

```bash
curl -X POST https://api.strails.io/v1/setusersettlementnetwork \
  -H "Content-Type: application/json" \
  -H "x-api-key: YOUR_SECRET_API_KEY" \
  -d '{
    "userId": "user_uniqueID",
    "network": "pol"
  }'
```

#### Request Parameters

<ParamField body="userId" type="string" required>
  The unique identifier of the user.
</ParamField>

<ParamField body="network" type="string" required>
  The settlement network. See [network values](#network-values).
</ParamField>

#### Response

```json
{
  "status": "Success",
  "response_code": "00",
  "message": "Default settlement network set successfully",
  "data": {
    "userId": "user_uniqueID",
    "settlementNetwork": "pol",
    "networkName": "Polygon",

    "destinationSource": "external_default"

```

<ResponseField name="data.destinationAddress" type="string">
  The address that will receive the user's onramp cNGN on this network.
</ResponseField>

<ResponseField name="data.destinationSource" type="string">

</ResponseField>

### POST /setfintechsettlementnetwork {#post-setfintechsettlementnetwork}

Sets the default settlement network for all of your users. It is a default, not an override: a user's own setting and their external default wallet network both take precedence.

<Warning>
  Strails can't check this setting against each user's wallets. A user with no address on the chosen network has their permanent virtual account deposits **held** rather than paid elsewhere, so register an external default wallet on that network for those users.
</Warning>

```bash
curl -X POST https://api.strails.io/v1/setfintechsettlementnetwork \
  -H "Content-Type: application/json" \
  -H "x-api-key: YOUR_SECRET_API_KEY" \
  -d '{
    "network": "pol"
  }'
```

#### Request Parameters

<ParamField body="network" type="string" required>
  The default settlement network. See [network values](#network-values).
</ParamField>

#### Response

```json
{
  "status": "Success",
  "response_code": "00",
  "message": "Default settlement network set successfully",
  "data": {
    "settlementNetwork": "pol",
    "networkName": "Polygon",
    "note": "Users without their own setting are paid on Polygon. A user with no address on Polygon will have their deposit held rather than paid elsewhere, so give those users an external wallet for it."
  }
}
```

#### Error Responses

```json
{
  "status": "Failed",
  "response_code": "01",
  "message": "\"polygonx\" is not a network Strails supports"
}
```
