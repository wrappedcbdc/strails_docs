Strails sends real-time event notifications to your configured webhook URL for all 22 critical operations across the platform. Every delivery is HMAC-signed so you can verify its authenticity, and any delivery that does not receive a `200` response is automatically retried with exponential backoff.

## Common payload fields

Every event delivered by Strails shares the following top-level fields regardless of event type.

| Field | Type | Description |
|---|---|---|
| `eventId` | string | Unique identifier for this specific event delivery. |
| `eventType` | string | The event name (e.g., `"user.onboarded"`, `"swap.completed"`). |
| `timestamp` | string | ISO 8601 timestamp of when the event was generated. |
| `requestId` | string | Identifier of the originating request or operation that triggered the event. |
| `fintechId` | string | Your fintech account identifier. |
| `version` | string | Schema version of the event payload (e.g., `"1.0.0"`). |
| `userId` | string | Identifier of the user associated with the event, where applicable. Omitted for fintech-level events. |
| `payload` | object | Event-specific data. Structure varies by event type - see each event section below. |

## HTTP headers

Strails includes the following headers on every webhook POST request.

| Header | Description |
|---|---|
| `X-Strails-Signature` | HMAC-SHA256 hex digest over `X-Strails-Timestamp` + `"."` + the raw request body, signed with your webhook secret. Verify this before processing the payload - see [HMAC Signatures](/hmac-signatures). |
| `X-Strails-Timestamp` | ISO 8601 timestamp of when the request was sent. Use this alongside the signature to prevent replay attacks. |
| `X-Webhook-ID` | Unique UUID for this specific delivery attempt. Use it to deduplicate retried deliveries. |
| `X-Strails-Event` | The event type name, matching the `eventType` field in the body (e.g., `"payments.confirmed"`). |

For signature verification implementation details, see the [HMAC Signatures](/hmac-signatures) page.

### `user.onboarded`

Fired when a user completes onboarding and is successfully registered under your fintech account.

**Key payload fields:** `firstName`, `lastName`, `onboardedAt`

```json
{
  "eventId": "uuid-event-id",

  "timestamp": "2026-07-02T10:30:00.000Z",
  "requestId": "req-12345",
  "fintechId": "fintech-uuid",
  "version": "1.0.0",
  "userId": "user-hash-12345",
  "payload": {
    "firstName": "John",
    "lastName": "Doe",
    "onboardedAt": "2026-07-02T10:30:00.000Z"
  }
}
```

## Retry behaviour

<Tip>
  Strails retries failed webhook deliveries using **exponential backoff**. A delivery is considered failed if your endpoint returns any HTTP status other than `2xx`, or if it does not respond within the timeout window.

  To avoid timeouts causing spurious retries, acknowledge receipt immediately by returning `HTTP 200` as soon as you receive the request, then process the payload asynchronously. Use the `X-Webhook-ID` header to deduplicate any events your system may receive more than once due to retries.
</Tip>

For full details on verifying the HMAC signature on each delivery, see the [HMAC Signatures](/hmac-signatures) page.
