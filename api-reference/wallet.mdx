The Wallet Management API gives you full control over the three wallet types in Strails. Your **Smart Wallet** is a contract-based EVM wallet that holds cNGN, USDC, and USDT and can be fintech- or Strails-controlled. Your **MPC Vault** provides multi-party computation custody for USDC and USDT. **External Wallets** are third-party addresses - cold storage, hot wallets, or custodial accounts - that you register on the platform for withdrawals and storage.

## Endpoints Overview

| Endpoint | Method | Description |
|---|---|---|
| [`/getfintechwallet`](#retrieve-the-fintech-wallet) | GET | Retrieve your Smart Wallet details and all registered External Wallets |
| [`/addexternalwallet`](#add-an-external-wallet) | POST | Register a new external wallet on your fintech account |
| [`/updateexternalwalletstatus`](#update-external-wallet-status) | PUT | Activate or deactivate a registered external wallet |
| [`/removeexternalwallet`](#remove-an-external-wallet) | DELETE | Remove an external wallet from your fintech account |
| [`/listuserwallets`](#retrieve-user-wallets) | POST | Retrieve all wallets for a specific end-user, including balances |
| [`/migrateuserwallets`](#migrate-user-wallets) | POST | Provision default wallets for users created before automated wallet provisioning |
| [`/balance/multi`](#fintech-system-wallet-balance) | GET | Get your fintech Smart Wallet balance across EVM networks |
| [`/balance/address`](#balance-for-a-specific-address) | POST | Get token balance for any specific EVM address across networks |
| [`/balance/user/:userId`](#end-user-balance) | GET | Get an end-user's wallet balances |

## Retrieve the Fintech Wallet

`GET /getfintechwallet`

Returns your fintech's Smart Wallet configuration and the complete list of registered External Wallets.

```bash
curl --request GET \
  --url "https://api.strails.io/getfintechwallet" \
  --header "Authorization: Bearer YOUR_API_KEY"
```

<ResponseField name="data" type="object">
  <Expandable title="data fields">
    <ResponseField name="fintechId" type="string">Unique identifier of your fintech account.</ResponseField>
    <ResponseField name="fintechName" type="string">Registered name of your fintech.</ResponseField>
    <ResponseField name="smartWallet" type="object">
      <Expandable title="smartWallet fields">
        <ResponseField name="address" type="string">On-chain address of the deployed Smart Wallet contract.</ResponseField>
        <ResponseField name="owner" type="string">EOA address that controls the Smart Wallet.</ResponseField>
        <ResponseField name="deployed" type="boolean">Whether the contract has been deployed on-chain.</ResponseField>
        <ResponseField name="createdAt" type="string">ISO 8601 timestamp of wallet creation.</ResponseField>
        <ResponseField name="saltVersion" type="string">Version identifier used during contract deployment (e.g. `v2`).</ResponseField>
        <ResponseField name="deploymentTxHash" type="string">Transaction hash of the deployment transaction.</ResponseField>
      </Expandable>
    </ResponseField>
    <ResponseField name="externalWallets" type="array">List of registered external wallets. Each entry contains `address`, `label`, `blockchain`, `type`, `addedAt`, `addedBy`, `status`, `isDefault`, and `purpose`.</ResponseField>
    <ResponseField name="totalUsers" type="number">Total number of end-users associated with your fintech.</ResponseField>
    <ResponseField name="createdAt" type="string">ISO 8601 timestamp when the fintech account was created.</ResponseField>
    <ResponseField name="updatedAt" type="string">ISO 8601 timestamp of the last update.</ResponseField>
  </Expandable>
</ResponseField>

## Add an External Wallet

`POST /addexternalwallet`

Registers an external wallet address on your fintech account. External wallets cannot be used for escrow operations. The address must be valid for the specified blockchain before it is accepted.

```bash
curl --request POST \
  --url "https://api.strails.io/addexternalwallet" \
  --header "Authorization: Bearer YOUR_API_KEY" \
  --header "Content-Type: application/json" \
  --data '{
    "address": "0xAbCd1234AbCd1234AbCd1234AbCd1234AbCd1234",
    "label": "Hot Wallet - Operations",
    "blockchain": "base",
    "type": "hot",
    "purpose": "Daily operations and withdrawals",
    "isDefault": true,
    "metadata": {
      "custodian": "Internal",
      "location": "AWS KMS",
      "backupExists": true
    }
  }'
```

<ParamField body="address" type="string" required>
  The wallet address to register on the platform.
</ParamField>

<ParamField body="blockchain" type="string" required>
  The blockchain network the wallet belongs to (e.g. `base`, `eth`, `bsc`).
</ParamField>

<ParamField body="type" type="string" required>
  The wallet custody type. One of `hot`, `cold`, `custodial`, or `other`.
</ParamField>

<ParamField body="label" type="string">
  A human-readable name for easy identification (e.g. `Cold Storage Wallet`).
</ParamField>

<ParamField body="purpose" type="string">
  The intended use of this wallet (e.g. `Daily operations and withdrawals`).
</ParamField>

<ParamField body="isDefault" type="boolean">
  Whether to set this wallet as your default external wallet. Defaults to `false`.
</ParamField>

<ParamField body="metadata" type="object">
  Additional custody information.
  <Expandable title="metadata fields">
    <ParamField body="custodian" type="string">
      Entity responsible for wallet custody (e.g. `Internal`, `Fireblocks`).
    </ParamField>
    <ParamField body="location" type="string">
      Key or wallet storage location (e.g. `AWS KMS`, `HSM`).
    </ParamField>
    <ParamField body="backupExists" type="boolean">
      Whether a secure backup of the wallet key exists.
    </ParamField>
  </Expandable>
</ParamField>

```json Response
{
  "status": "success",
  "response_code": "00",
  "message": "External wallet added successfully",
  "data": {
    "wallet": {
      "address": "0xAbCd1234AbCd1234AbCd1234AbCd1234AbCd1234",
      "status": "active",
      "type": "hot",
      "blockchain": "base"
    }
  }
}
```

**Error responses**

```json Invalid address format
{
  "status": "error",
  "response_code": "01",
  "message": "Validation error",
  "error": "Invalid wallet address format"
}
```

```json Wallet already registered
{
  "status": "error",
  "response_code": "01",
  "message": "Wallet already exists",
  "error": "This wallet address is already registered"
}
```

## Update External Wallet Status

`PUT /updateexternalwalletstatus`

Activates or deactivates a registered external wallet. Inactive wallets cannot receive transfers from the platform.

```bash
curl --request PUT \
  --url "https://api.strails.io/updateexternalwalletstatus" \
  --header "Authorization: Bearer YOUR_API_KEY" \
  --header "Content-Type: application/json" \
  --data '{
    "address": "0xabcdefabcdefabcdefabcdefabcdefabcdefabcd",
    "status": "inactive"
  }'
```

<ParamField body="address" type="string" required>
  The wallet address to update.
</ParamField>

<ParamField body="status" type="string" required>
  The new status for the wallet. Must be either `active` or `inactive`.
</ParamField>

```json Response
{
  "status": "success",
  "response_code": "00",
  "message": "External wallet status updated successfully",
  "data": {
    "address": "0xabcdefabcdefabcdefabcdefabcdefabcdefabcd",
    "status": "inactive"
  }
}
```

**Error responses**

```json Wallet not found
{
  "status": "error",
  "response_code": "02",
  "message": "Wallet not found",
  "error": "No external wallet found with the provided address"
}
```

```json Invalid status value
{
  "status": "error",
  "response_code": "01",
  "message": "Validation error",
  "error": "Status must be 'active' or 'inactive'"
}
```

## Migrate User Wallets

`POST /migrateuserwallets`

Provisions default wallets for end-users who were created before automated wallet provisioning was enabled. Use this endpoint to bring legacy users up to the current wallet structure.

<Warning>
  Ensure all funds have been transferred out of any existing legacy wallets before calling this endpoint. Migration may result in new wallet addresses being issued for affected users.
</Warning>

```bash
curl --request POST \
  --url "https://api.strails.io/migrateuserwallets" \
  --header "Authorization: Bearer YOUR_API_KEY" \
  --header "Content-Type: application/json" \
  --data '{
    "userId": ["userId_abc123", "userId_def456"],
    "force": true
  }'
```

<ParamField body="userId" type="array" required>
  A list of user identifiers (hashes or UUIDs) to migrate. You can pass multiple user IDs in a single call.
</ParamField>

<ParamField body="force" type="boolean">
  When `true`, the migration proceeds even if a user already has partial wallet data. Defaults to `false`.
</ParamField>

<ResponseField name="data" type="object">
  <Expandable title="data fields">
    <ResponseField name="requestId" type="string">Unique identifier for this migration batch.</ResponseField>
    <ResponseField name="totalProcessed" type="number">Total number of user IDs submitted.</ResponseField>
    <ResponseField name="created" type="number">Number of wallets newly created.</ResponseField>
    <ResponseField name="migrated" type="number">Number of wallets migrated from a legacy structure.</ResponseField>
    <ResponseField name="skipped" type="number">Number of users skipped (wallet already exists).</ResponseField>
    <ResponseField name="failed" type="number">Number of users for whom wallet creation failed.</ResponseField>
    <ResponseField name="results" type="array">Per-user migration outcome. Each entry includes `userId`, `status`, `walletAddress`, `deployed`, and optionally `reason`.</ResponseField>
  </Expandable>
</ResponseField>

```json Response
{
  "status": "Success",
  "response_code": "00",
  "message": "Wallet migration completed",
  "data": {
    "requestId": "migrate_fintech123_1706457600000",
    "totalProcessed": 3,
    "created": 2,
    "migrated": 0,
    "skipped": 1,
    "failed": 0,
    "results": [
      { "userId": "abc123", "status": "created", "walletAddress": "0x...", "deployed": true },
      { "userId": "def456", "status": "created", "walletAddress": "0x...", "deployed": true },
      { "userId": "ghi789", "status": "skipped", "walletAddress": "0x...", "reason": "Wallet already exists" }
    ]
  }
}
```

## Fintech System Wallet Balance

`GET /balance/multi`

Returns your fintech's own Smart Wallet token balance across one or more EVM networks. Use the `networks` query parameter to limit the check to specific chains.

```bash
curl --request GET \
  --url "https://api.strails.io/balance/multi?token=CNGN&networks=base,eth,bsc" \
  --header "Authorization: Bearer YOUR_API_KEY"
```

<ParamField query="token" type="string">
  The token ticker to query (e.g. `CNGN`, `USDC`, `USDT`). Defaults to `CNGN`.
</ParamField>

<ParamField query="networks" type="string">
  Comma-separated list of EVM network keys to check (e.g. `base,eth,bsc`). Defaults to all supported EVM networks.
</ParamField>

<ResponseField name="data" type="object">
  <Expandable title="data fields">
    <ResponseField name="token" type="string">The token that was queried.</ResponseField>
    <ResponseField name="walletAddress" type="string">Your Smart Wallet address.</ResponseField>
    <ResponseField name="totalBalance" type="string">Aggregate balance across all checked networks.</ResponseField>
    <ResponseField name="hasBaseNetworkFunds" type="boolean">Whether the Base network holds a non-zero balance.</ResponseField>
    <ResponseField name="hasCrossNetworkFunds" type="boolean">Whether any non-Base network holds a non-zero balance.</ResponseField>
    <ResponseField name="baseNetworkBalance" type="string">Balance on the Base network.</ResponseField>
    <ResponseField name="crossNetworkBalance" type="string">Combined balance on all non-Base networks.</ResponseField>
    <ResponseField name="bridgingRequired" type="boolean">Whether a cross-chain bridge is needed to consolidate funds.</ResponseField>
    <ResponseField name="networkBalances" type="array">Per-network balance entries. Each entry contains `network` and `balance`, plus an optional `error` if the RPC call failed.</ResponseField>
    <ResponseField name="walletsWithFunds" type="array">Subset of `networkBalances` showing only networks with a non-zero balance.</ResponseField>
    <ResponseField name="checkedAt" type="string">ISO 8601 timestamp of when the balance check was performed.</ResponseField>
  </Expandable>
</ResponseField>

```json Response
{
  "status": "Success",
  "response_code": "00",
  "message": "Multi-network balance retrieved",

    "networkBalances": [
      { "network": "base", "balance": "1299.974550" },

    "walletsWithFunds": [
      { "network": "base", "balance": "1299.974550" }
    ],
    "checkedAt": "2026-07-22T09:12:49.339Z"
  }
}
```

## End-User Balance

`GET /balance/user/:userId`

Returns the token balances across all wallets provisioned for a specific end-user. Balances are resolved from the user's Smart Wallet and all additional network addresses associated with the user.

```bash
curl --request GET \
  --url "https://api.strails.io/balance/user/abc123?token=CNGN" \
  --header "Authorization: Bearer YOUR_API_KEY"
```

<ParamField path="userId" type="string" required>
  The unique identifier of the end-user whose balance you want to retrieve.
</ParamField>

<ParamField query="token" type="string">
  The token ticker to query (e.g. `CNGN`, `USDC`, `USDT`). Defaults to `CNGN`.
</ParamField>

<ResponseField name="data" type="object">
  <Expandable title="data fields">
    <ResponseField name="userId" type="string">The user ID that was queried.</ResponseField>
    <ResponseField name="token" type="string">The token that was queried.</ResponseField>
    <ResponseField name="totalBalance" type="string">Aggregate balance across all the user's wallets.</ResponseField>
    <ResponseField name="networkBalances" type="array">Per-network entries containing `network`, `walletAddress`, and `balance`, plus an optional `error` if the RPC call failed.</ResponseField>
    <ResponseField name="checkedAt" type="string">ISO 8601 timestamp of when the balance check was performed.</ResponseField>
  </Expandable>
</ResponseField>

```json Response
{
  "status": "Success",
```
