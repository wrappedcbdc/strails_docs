The Strails REST API gives your fintech platform full programmatic control over user onboarding, virtual account management, cNGN wallets, FX trading, payouts, and webhook notifications. All requests are authenticated with your secret API key, and long-running operations follow a consistent async pattern using `requestId` polling or webhook callbacks.

## Base URLs

Use the test environment during integration and switch to the production URL before go-live. The two environments are completely isolated — keys, users, and funds do not carry over.

**Test**

```bash
https://beta.stablesrail.io/v1/
```

**Production**

```bash
https://api.strails.io/v1/
```

## Authentication

Every request must include your secret API key in the `x-api-key` header. You can retrieve and rotate your keys from the Strails dashboard.

```bash
x-api-key: YOUR_SECRET_API_KEY
```

<Warning>
  Never expose your secret API key in client-side code or public repositories. All requests to the Strails API must originate from your backend server.
</Warning>

## Async Processing

Some operations — such as user onboarding and wallet provisioning — are processed asynchronously. When you submit one of these requests, the API immediately returns a `requestId` and a `status` of `"processing"`. You can then:

1. **Poll** the corresponding status endpoint (e.g. `POST /onboardstatus`) with the `requestId` until the status changes to `"completed"` or `"failed"`.
2. **Listen for webhooks** — Strails fires a webhook event to your registered callback URL when the operation finishes, letting you avoid repeated polling.

```json
{
  "data": {
    "requestId": "7898f29e-10a6-4b2b-9496-f4ee50549fd4",
    "status": "processing",
    "estimatedCompletionTime": "2-5 minutes"
  }
}
```

<Info>
  See the [Webhooks](/api-reference/webhook-events) reference for the full list of async event types and payload schemas.
</Info>
